# AI Lead Assistant

**AI Lead Assistant** — Telegram-бот для первичного приёма и структурирования заявок на разработку AI-решений. Бот ведёт диалог с потенциальным клиентом, извлекает сведения о проекте с помощью OpenAI, показывает заявку для подтверждения, сохраняет её в SQLite и уведомляет оператора в Telegram.

**Демонстрация:** [@glazounov_ai_leads_bot](https://t.me/glazounov_ai_leads_bot)

> MVP работает в Docker на постоянно включённом компьютере разработчика. Доступность бота зависит от работы компьютера, Docker, сети и Telegram; облачное размещение пока не реализовано.

## Возможности

- Диалог с клиентом на естественном языке через Telegram.
- Извлечение и накопление сведений о заявке с помощью OpenAI (`gpt-4o-mini`).
- Сбор имени, контакта и бизнес-задачи; при наличии — компании, типа решения, интеграций, сроков и бюджета.
- Просмотр заявки перед отправкой и подтверждение через кнопки Telegram.
- Сохранение подтверждённой заявки в SQLite **до** отправки уведомления оператору.
- Уведомление оператора о новой заявке и фиксация статуса доставки.
- Операторские команды для просмотра заявок и ручной повторной отправки уведомлений.
- Постоянное хранилище SQLite в Docker volume.
- Автоматические тесты основных компонентов.

## Как работает

1. Клиент открывает бота и отправляет `/start`.
2. Описывает задачу и отвечает на вопросы ассистента.
3. OpenAI помогает выделить структурированные данные заявки.
4. Бот показывает сводку с кнопками подтверждения или исправления.
5. После подтверждения заявка сохраняется в SQLite.
6. Бот пытается отправить уведомление оператору. Результат доставки записывается отдельно от факта принятия заявки.

**Важно:** сбой отправки уведомления не отменяет уже принятую заявку. Повторно оформлять её клиенту не нужно.

## Архитектура

```text
Клиент в Telegram
       |
       v
Telegram Bot (python-telegram-bot)
       |
       +--> OpenAI (gpt-4o-mini) --> извлечение полей заявки

                                  +--> /leads, /lead, /pending, /retry
```

## Настройка и запуск

### Требования

- Docker с поддержкой Docker Compose.
- Токен Telegram-бота, полученный через [@BotFather](https://t.me/BotFather).
- Ключ OpenAI API.
- Telegram ID оператора для личного чата с ботом.

### 1. Подготовка окружения

Скопируйте `.env.example` в `.env` и заполните реальные значения:

```powershell
Copy-Item .env.example .env
```

Переменные окружения:

```dotenv
TELEGRAM_BOT_TOKEN=replace_with_telegram_bot_token
OPENAI_API_KEY=replace_with_openai_api_key
TELEGRAM_OPERATOR_CHAT_ID=replace_with_operator_telegram_user_id
```

Значения и названия переменных сверяйте с `compose.yaml` и настройками приложения при изменении конфигурации.

**Никогда не публикуйте `.env` с действующими секретами.** Файл исключён через `.gitignore`.

### 2. Запуск

Из корня проекта:

```powershell
docker compose up -d --build
```

Проверка состояния:

```powershell
docker compose ps
```

После запуска откройте [бота](https://t.me/glazounov_ai_leads_bot) и отправьте `/start`.

### 3. Остановка и перезапуск

```powershell
docker compose restart ai-lead-assistant
```

Для остановки:

```powershell
docker compose down
```

**Не используйте `docker compose down -v`, если хотите сохранить заявки:** эта команда удаляет именованные volumes проекта.

## Команды Telegram

| Команда | Назначение |
|---|---|
| `/start` | Начать диалог для оформления заявки |
| `/cancel` | Прервать текущий диалог |
| `/leads` | Показать последние заявки (оператор) |
| `/lead UUID` | Показать подробности заявки (оператор) |
| `/pending` | Показать заявки с неподтверждённой доставкой (оператор) |
| `/retry UUID` | Повторно отправить уведомление по допустимой заявке (оператор) |

Операторские команды доступны только настроенному пользователю в личном чате. `/retry` не повторяет отправку для заявок со статусами `sent` или `sending`.

## Состояния доставки

| Статус | Значение |
|---|---|
| `not_sent` | Заявка принята, отправка ещё не началась |
| `sending` | Отправка начата; результат ещё не зафиксирован |
| `sent` | Telegram подтвердил отправку уведомления |
| `uncertain` | Доставка не подтверждена; требуется проверка или повтор |

Принятие заявки (`submitted`) и доставка уведомления (`delivery_status`) учитываются отдельно. События отправки фиксируются в `delivery_attempts`.

При временной сетевой ошибке предусмотрена одна повторная попытка отправки. Для ручного восстановления используется `/pending` и `/retry UUID`. Состояние `sending` после аварийного завершения требует отдельной проверки оператором; автоматическое разблокирование не реализовано.

## Ограничения MVP и планы

- Улучшить последовательность уточняющих вопросов: сейчас бот может одновременно спросить дополнительные сведения и предложить подтверждение заявки.
- Надёжнее сохранять Telegram ID клиента как контакт для последующей связи.
- Дополнить испытания отказов SQLite и Telegram, включая прерывание процесса в момент отправки.
- Реализовать ручную обработку заявок, застрявших в статусе `sending`.
- Добавить мониторинг доступности, резервное копирование SQLite и безопасную эксплуатационную конфигурацию.
- В дальнейшем рассмотреть веб-интерфейс, CRM-интеграции и облачное развёртывание.

## Безопасность

- Действующие API-ключи и токены должны храниться только в `.env` или защищённом хранилище секретов.
- База заявок и другие runtime-данные исключены из Git.
- Не публикуйте логи, содержащие токены или персональные данные клиентов.
- Перед публичной эксплуатацией необходимо проверить актуальность токена Telegram и ограничить подробное логирование HTTP-запросов.
